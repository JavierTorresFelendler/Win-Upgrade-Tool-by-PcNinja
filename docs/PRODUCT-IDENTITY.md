# Product identity and portable download contract

- Display name: **Windows Upgrade Assistant By PcNinja**.
- Fixed executable/Release asset name: `Windows-Upgrade-Assistant-By-PcNinja.exe`.
- No V1/RC/build suffix in the GUI branding or executable name. Version/commit
  identity stays in file properties, startup diagnostics, explicit CLI `version`
  and machine-readable `status --json` (`version` and complete `build`).
- ProductIdentity reads assembly informational-version metadata; it does not
  infer versions from a renamed executable. Existing history/log paths stay
  unchanged to retain previous attempts. Internal namespaces/repository URL do
  not need renaming to change the public product.
- GitHub Release assets use the uploaded filename; they are not the autogenerated
  source-code ZIP/tar archives. Each version has its own tag and checksum even
  when the EXE filename stays constant. Existing release assets remain immutable.
- After an authorized **stable** publication, the public convenience URL can be:
  `https://github.com/JavierTorresFelendler/pcninja-win11-upgrade-assistant/releases/latest/download/Windows-Upgrade-Assistant-By-PcNinja.exe`.
  This is not an active download promise: the current release is RC6, and the
  release workflow still requires RC metadata. Stable publication is separate.
- A future app updater must resolve a version-pinned Release asset and verify
  version/hash/size. Do not download a mutable latest URL after checking a manifest
  for a different version. No updater/feed or public stable release is added here.

References: [GitHub release links](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases),
[Release assets API](https://docs.github.com/en/rest/releases/assets).
